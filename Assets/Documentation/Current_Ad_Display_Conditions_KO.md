# 현재 광고 표시 조건 정리

마지막 확인일: 2026-05-15

이 문서는 현재 코드 기준 광고가 언제 로드되고, 언제 실제로 표시되는지 정리한 문서입니다.

확인 기준 코드:

- `Assets/Scripts/GameMainUIController.cs`
- `Assets/Scripts/GameManager.cs`

## 전체 공통 조건

- 실제 Google Mobile Ads 코드는 Unity Editor가 아닌 Android/iOS 빌드에서만 컴파일됩니다.
  - 조건: `#if !UNITY_EDITOR && (UNITY_ANDROID || UNITY_IOS)`
- Unity Editor 또는 모바일이 아닌 플랫폼에서는 실제 광고가 뜨지 않습니다.
- Editor에서는 테스트 편의를 위해 보상형 광고 흐름이 즉시 성공 처리됩니다.
- Development Build에서는 `Debug.isDebugBuild`가 true이고, `ShouldDisableAdsForDevelopmentBuild()`가 true를 반환합니다.

Development Build일 때:

- 실제 광고 로드/표시를 전부 건너뜁니다.
- 배너 영역을 숨깁니다.
- 힌트/스킵/하트 보상은 광고 없이 바로 지급됩니다.
- 스테이지 전환 전면 광고도 건너뜁니다.

릴리즈 Android/iOS 빌드일 때:

- 실제 광고 로드/표시가 가능합니다.
- 현재 코드상 릴리즈 AdMob 광고 단위 ID를 사용합니다.

주의:

- 테스트 광고 ID는 코드에 존재합니다.
- 하지만 현재 Development Build에서는 광고 로드 자체를 막기 때문에, `Debug.isDebugBuild == true`인 빌드에서는 테스트 광고 ID도 보통 사용되지 않습니다.

## 광고 제거 상태

현재 광고 제거 권한 키:

- `RemoveAdsEntitled`

현재 기본값:

- `false`

현재 동작:

- 광고 제거 버튼은 아직 실제 구매가 연결되지 않은 placeholder 상태입니다.
- 코드 안에서 `RemoveAdsEntitled`를 true로 바꾸는 실제 구매 로직은 없습니다.
- `RemoveAdsEntitled == true`일 때 영향을 받는 부분은 힌트/스킵 보조 기능과 스테이지 전환 전면 광고입니다.
  - 힌트/스킵 횟수가 0일 때 `AD` 대신 충전 타이머가 표시됩니다.
  - 힌트/스킵 횟수가 0이어도 보상형 광고를 보여주지 않습니다.
  - 스테이지 전환 전면 광고는 로드/표시하지 않습니다.

현재 광고 제거가 막지 않는 것:

- 배너 광고
- 하트 충전 보상형 광고

즉, 현재 코드 기준으로는 광고 제거가 “전체 광고 제거”가 아니라, 힌트/스킵 AD 흐름과 스테이지 전환 전면 광고만 막는 상태입니다.

## 배너 광고

시작 위치:

- UI 초기화 중 `InitializeBannerAd()`에서 시작됩니다.

실제로 표시되는 조건:

- Android 또는 iOS 빌드입니다.
- Unity Editor가 아닙니다.
- Development Build가 아닙니다.
- 현재 플랫폼에 맞는 배너 광고 단위 ID가 있습니다.
- 배너 광고 로드에 성공합니다.

표시 방식:

- 하단 anchored adaptive banner를 사용합니다.
- `LoadBannerAd()`에서 `BannerView`를 생성합니다.
- 배너 로드 성공 시 `bannerView.Show()`를 호출합니다.
- 배너가 예상되거나 로드되면 하단 UI가 배너 높이만큼 공간을 비웁니다.

표시되지 않는 경우:

- Unity Editor
- Android/iOS가 아닌 플랫폼
- Development Build
- 광고 단위 ID 없음
- 배너 로드 실패

현재 주의점:

- `RemoveAdsEntitled`가 true여도 배너 광고 로드/표시를 막지 않습니다.

## 힌트 보상형 광고

트리거:

- 유저가 힌트 버튼을 누를 때

광고 판단 전에 필요한 조건:

- `GameManager`가 있어야 합니다.
- 힌트 solver가 이미 실행 중이면 안 됩니다.
- 현재 상태에서 보여줄 수 있는 힌트 경로가 있어야 합니다.

우선순위:

1. 스테이지 임시 무료 힌트가 있으면
   - 힌트를 보여줍니다.
   - 임시 힌트를 1개 소비합니다.
   - 광고 없음.
2. 일반 힌트 충전 횟수가 있으면
   - 힌트를 보여줍니다.
   - 일반 힌트를 1개 소비합니다.
   - 광고 없음.
3. Development Build이면
   - 개발용 보상 로그를 남깁니다.
   - 힌트를 바로 보여줍니다.
   - 광고 없음.
4. 광고 제거 상태이면
   - 광고를 보여주지 않습니다.
   - 충전 대기 스낵바/타이머를 보여줍니다.
5. Android/iOS 릴리즈 빌드이면
   - 보상형 광고를 시도합니다.
   - 보상을 받으면 힌트를 보여줍니다.
6. Editor 또는 비모바일 플랫폼이면
   - editor 보상 로그를 남깁니다.
   - 힌트를 바로 보여줍니다.
   - 광고 없음.

현재 구현상 특징:

- 힌트 광고는 `TryShowAssistRewardedAd("hint", ...)`를 사용합니다.
- 이 함수는 현재 스킵 보상형 광고와 같은 `stageSkipRewardedAd` 인스턴스/광고 단위 흐름을 사용합니다.
- 광고가 준비되어 있지 않으면:
  - `hint_reward_ad_not_ready` 로그를 남깁니다.
  - stage skip rewarded ad 로드를 요청합니다.
  - 힌트는 즉시 지급되지 않습니다.

## 스테이지 스킵 보상형 광고

트리거:

- 유저가 스킵 버튼을 누를 때

우선순위:

1. 스킵 충전 횟수가 있으면
   - 즉시 다음 스테이지로 이동합니다.
   - 스킵 충전을 1개 소비합니다.
   - 광고 없음.
2. Development Build이면
   - 개발용 보상 로그를 남깁니다.
   - 즉시 다음 스테이지로 이동합니다.
   - 광고 없음.
3. 광고 제거 상태이면
   - 광고를 보여주지 않습니다.
   - 충전 대기 스낵바/타이머를 보여줍니다.
4. Android/iOS 릴리즈 빌드이면
   - 보상형 광고를 시도합니다.
   - 보상을 받고 광고가 닫히면 다음 스테이지로 이동합니다.
5. Editor 또는 비모바일 플랫폼이면
   - editor 보상 로그를 남깁니다.
   - 즉시 다음 스테이지로 이동합니다.
   - 광고 없음.

광고가 준비되어 있지 않으면:

- `stage_skip_reward_ad_not_ready` 로그를 남깁니다.
- 스킵 보상형 광고 로드를 요청합니다.
- 즉시 스킵되지는 않습니다.

## 하트 충전 보상형 광고

트리거:

- 게임오버 또는 수동 리트라이로 하트가 감소합니다.
- 현재 하트가 0이 됩니다.
- 하트 충전 팝업이 열립니다.

제안 우선순위:

1. 세션 플레이 보상이 남아 있으면
   - 광고 대신 세션 보상 모드로 팝업을 보여줍니다.
   - 광고 없이 하트 충전이 가능합니다.
2. 세션 플레이 보상이 없으면
   - 보상형 광고 모드로 팝업을 보여줍니다.
   - 필요하면 보상형 광고를 로드합니다.

실제 광고 표시 조건:

- 유저가 하트 충전 광고 버튼을 누릅니다.
- Android 또는 iOS 빌드입니다.
- Unity Editor가 아닙니다.
- Development Build가 아닙니다.
- `rewardedAd`가 존재합니다.
- `rewardedAd.CanShowAd()`가 true입니다.

보상:

- 광고 보상 콜백을 받으면 하트가 최대치까지 충전됩니다.
- 현재 최대 하트는 5개입니다.
- 하트 충전 팝업이 닫힙니다.

광고가 표시되지 않는 경우:

- 세션 플레이 보상이 있어서 광고 없이 충전하는 경우
- Unity Editor
- Android/iOS가 아닌 플랫폼
- Development Build
- 보상형 광고가 아직 준비되지 않은 경우

광고가 준비되어 있지 않으면:

- UI에 광고 준비 중 상태를 표시합니다.
- `LoadRewardedAd()`를 호출합니다.
- Editor/Development Build 테스트 흐름을 제외하면, 실제 보상을 받기 전까지 하트는 충전되지 않습니다.

현재 주의점:

- `RemoveAdsEntitled`가 true여도 하트 충전 보상형 광고 흐름을 우회하지 않습니다.

## 스테이지 전환 전면 광고

트리거:

- 스테이지 클리어 후 `LoadNextStageAfterDelay()` 흐름에 들어갑니다.
- 다음 스테이지로 넘어가기 전에 `ShowStageTransitionInterstitialIfNeeded(completedStageIndex, ...)`가 호출됩니다.

실제 광고 표시 조건:

- 클리어한 스테이지가 12 이상입니다.
- 앱 세션 시작 또는 마지막 전면 광고 표시 이후 180초 이상 지났습니다.
- 마지막 전면 광고 표시 이후 최소 5스테이지 이상 클리어했습니다.
- 광고 제거 유저가 아닙니다.
- Development Build가 아닙니다.
- Android 또는 iOS 빌드입니다.
- Unity Editor가 아닙니다.
- 전면 광고가 로드되어 있고 `CanShowAd()`가 true입니다.

예시:

- 11스테이지 클리어: 전면 광고 대상 아님
- 12스테이지 이상이어도 180초가 지나지 않았으면 전면 광고 대상 아님
- 12스테이지 이상, 180초 경과, 마지막 광고 이후 5스테이지 이상, 광고 준비 완료면 전면 광고 대상
- 15스테이지 자체는 더 이상 특별 조건이 아닙니다.

광고 대상이 아니면:

- 바로 다음 스테이지 진행 콜백을 실행합니다.
- 광고 없이 다음 스테이지로 넘어갑니다.

광고 대상이지만 광고가 준비되어 있지 않으면:

- `LoadStageTransitionInterstitialAd()`를 호출합니다.
- 바로 다음 스테이지 진행 콜백을 실행합니다.
- 그 전환에서는 광고 없이 다음 스테이지로 넘어갑니다.
- 마지막 광고 시간/스테이지는 갱신하지 않습니다.

전면 광고가 실제로 열리면:

- 현재 앱 세션 기준 마지막 광고 시간과 클리어 스테이지를 갱신합니다.

전면 광고가 닫히거나 표시 실패하면:

- 다음 스테이지 진행 콜백을 실행합니다.
- 현재 전면 광고 객체를 제거합니다.
- Development Build가 아니고 광고 제거 유저가 아니라면 새 전면 광고 로드를 요청합니다.

현재 주의점:

- 스테이지 전환 전면 광고 pacing은 세션 단위입니다. 앱을 재실행하면 메모리상의 cooldown/stage-gap 상태는 초기화됩니다.

## 광고 로딩 흐름

UI 초기화 시:

- `InitializeBannerAd()`가 실행됩니다.
- Android/iOS 릴리즈 빌드에서는 `MobileAds.Initialize()` 이후 아래 광고 로드를 큐에 넣습니다.
  - 배너 광고
  - 하트 충전 보상형 광고
  - 힌트/스킵 보상형 광고
  - 스테이지 전환 전면 광고

광고 닫힘/실패 후:

- 하트 보상형 광고:
  - 현재 rewarded ad 제거
  - 새 rewarded ad 로드
- 힌트/스킵 보상형 광고:
  - 현재 stage skip rewarded ad 제거
  - 새 stage skip rewarded ad 로드
- 스테이지 전환 전면 광고:
  - 현재 interstitial 제거
  - Development Build가 아니고 광고 제거 유저가 아니면 새 interstitial 로드

| 광고 타입 | 실제 표시 조건 | 보상/효과 | Development Build | Editor |
| --- | --- | --- | --- | --- |
| 배너 | Android/iOS 릴리즈, 로드 성공 | 하단 배너 표시 | 숨김/로드 없음 | 실제 광고 없음 |
| 힌트 보상형 | 힌트 0개, 임시 힌트 없음, 광고 제거 아님, 힌트 경로 있음, 광고 준비됨 | 힌트 표시 | 무료 힌트 | 무료 힌트 |
| 스킵 보상형 | 스킵 0개, 광고 제거 아님, 광고 준비됨 | 스테이지 스킵 | 무료 스킵 | 무료 스킵 |
| 하트 충전 보상형 | 하트 0개, 세션 무료 충전 없음, 광고 준비됨 | 하트 5개 충전 | 무료 충전 | 무료 충전 |
