# 규칙 수정 단계별 실행 계획서

## 목적

- [rule_check.md](/Users/economy/Unity/ZeroStep/Assets/rules/rule_check.md) 에서 확인된 불일치 항목을 한 번에 모두 수정하지 않고, 6단계로 나눠서 순차적으로 반영하기 위한 실행 계획서다.
- 각 단계는 독립적으로 커밋하거나 검증할 수 있도록 나눴다.
- 기본 기준은 [TILE_RULES.md](/Users/economy/Unity/ZeroStep/Assets/rules/TILE_RULES.md) 를 공식 규칙 문서로 보고, 런타임 구현을 문서에 맞추는 것이다.

## 공통 원칙

- [ ] 한 단계가 끝나기 전에는 다음 단계 구현에 들어가지 않는다.
- [ ] 각 단계 종료 시 해당 단계 범위만 수동 테스트 또는 정적 검증을 먼저 한다.
- [ ] 단계 간 영향이 큰 공통 함수 수정은 가능한 앞 단계에서 정리하고, 뒤 단계는 그 결과를 사용한다.
- [ ] 모든 단계 완료 후에만 문서 최종 동기화와 전체 재검증을 수행한다.

## 1단계: 승리/패배 조건 단일화

### 목표

- 현재 런타임의 승리/패배 조건을 문서와 맞는 형태로 먼저 정리한다.
- 게임 루프의 종료 조건을 먼저 고정해서 이후 단계 수정 시 기준점이 흔들리지 않게 만든다.

### 수정 범위

- `GameManager`의 승리 판정 로직
- `GameManager`의 패배 판정 로직
- 클리어/실패 이벤트 로그 분기

### 작업 체크리스트

- [ ] `CheckVictoryCondition()` 특례 클리어 제거 또는 비활성화
- [ ] `CheckStageClear()`를 유일한 공식 승리 판정으로 정리
- [ ] `TrackStageCleared()`의 `clear_type` 정리
- [ ] 데드락 외 패배 경로 목록 정리
- [ ] `FixedKnot` 실패 경로 유지/제거 정책 확정
- [ ] `TrackStageFailed(reason)` 값 정리
- [ ] 문서와 다른 숨은 게임오버 진입점이 없는지 확인

### 완료 기준

- [ ] 승리 조건이 하나로 고정됨
- [ ] 패배 조건 목록이 명시적으로 정리됨
- [ ] `GameManager` 종료 조건만 봐도 문서와 비교 가능함

### 단계 종료 검증

- [ ] 마지막 타일 특례 클리어가 발생하지 않는지 확인
- [ ] 모든 활성 타일 count가 0일 때만 클리어되는지 확인
- [ ] 데드락 처리 결과 확인
- [ ] `FixedKnot` 관련 실패 동작이 이번 단계 정책과 일치하는지 확인

- [ ] 목적지 인접 여부 검사 공통화

- [ ] `ShortCircuit` 출발 방향 검사 위치 고정
- [ ] `FixedKnot` 순서 검사 위치 고정

- [ ] 특수 효과 적용 순서 통일

### 권장 구현 구조

## 3단계: `TwinLink`, `Igniter`, `BlindCurtain` 규칙 수정

### 목표

- 문서와 가장 크게 어긋나는 특수 타일 3종을 개별 규칙에 맞게 수정한다.
- 이 단계는 "특수 타일 핵심 규칙 수정" 단계다.

### 수정 범위

- `TwinLinkTile`
- `IgniterTile`
- `BlindCurtainTile`
- 해당 타일을 호출하는 `GameManager` 연결부

### 작업 체크리스트

#### `TwinLink`

- [ ] 현재 count 동기화 방식 제거
- [ ] partner 직접 `-1` 감소 방식으로 변경
- [ ] partner 감소 실패 조건 설계
- [ ] 시각 효과와 수치 처리 분리

#### `Igniter`

- [ ] 일반 타일과 동일 감소 규칙으로 정리
- [ ] 진입 시 Hidden 활성화만 남기도록 정리
- [ ] 떠날 때 소멸 규칙 유지/제거 확정
- [ ] 시작 타일이 `Igniter`일 때 Hidden 초기 활성화 처리 추가

#### `BlindCurtain`

- [ ] 전역 `?` 전환 효과 제거
- [ ] 강제 `count = 1` 여부 재정리
- [ ] 시각 아이콘 전용 타일로 단순화

### 완료 기준

- [ ] `TwinLink`가 문서대로 직접 감소함
- [ ] `Igniter`가 문서대로 일반 타일 + 활성화 트리거로 동작함
- [ ] `BlindCurtain`이 문서대로 시각 전용 타일이 됨

### 단계 종료 검증

- [ ] `TwinLink` 대표 스테이지 수동 테스트
- [ ] `Igniter` 진입 후 Hidden 활성화 테스트
- [ ] 시작 타일 `Igniter` 케이스 테스트
- [ ] `BlindCurtain` 밟아도 전체 숫자가 `?`로 바뀌지 않는지 확인

## 5단계: `Hidden`, `Blackout`, `ShortCircuit` 보완

### 목표

- 규칙 자체는 크게 틀리지 않지만, 문서와 표현 방식이 어긋난 항목들을 마무리 정리한다.
- 이 단계는 규칙-연출 경계를 정리하는 단계다.

### 수정 범위

- `HiddenTile`
- `BlackoutTile`
- `ShortCircuitTile`
- 관련 `GameManager` 판정부

### 작업 체크리스트

#### `Hidden`

- [ ] 콜라이더 기반 진입 차단 구조를 명확히 정리
- [ ] 진입 가능 여부 판정 코드와 역할 중복 제거

#### `Blackout`

- [ ] 규칙 변경이 아니라 시각 연출이라는 구조를 코드에서 분리
- [ ] 숫자 `?` 처리 위치 정리

#### `ShortCircuit`

- [ ] 진입 방향도 제한할지 최종 결정
- [ ] `EntryCell` / `IsValidEntryFrom()` 사용 여부 확정
- [ ] 사용하지 않을 경우 죽은 코드 제거
- [ ] 사용할 경우 실제 이동 판정에 연결

### 완료 기준

- [ ] `Hidden`, `Blackout`, `ShortCircuit`의 규칙과 연출이 명확히 분리됨
- [ ] 주석과 실제 코드가 같은 의미를 가리킴

### 단계 종료 검증

- [ ] `Hidden` 활성화 전후 진입 테스트
- [ ] `Blackout` 시각 효과와 이동 규칙 분리 확인
- [ ] `ShortCircuit` 진입/출발 규칙 최종 정책 테스트
