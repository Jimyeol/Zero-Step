# ZeroStep 타일 규칙 개발 문서

이 문서는 현재 저장소의 스테이지 데이터, 시뮬레이터(`stage_simulator.html`), 검증기(`validate_stages.py`), 생성기(`generate_stages.py`)를 기준으로 타일 규칙을 개발 문서 관점에서 정리한 것이다.

## 1. 목적과 범위

- 대상: 스테이지 데이터 작성자, 시뮬레이터 유지보수자, 게임 로직 구현자
- 범위: 기본 이동 규칙, 승리 조건, 타일 소멸/음수 조건, 특수 타일 동작
- 기준 용어:
  - `count`: 해당 타일이 앞으로 몇 번 더 소비될 수 있는지 나타내는 값
  - `이동`: 상하좌우 인접 타일로의 1회 이동
  - `출발 타일`: 현재 이동을 시작하는 타일
  - `목적지 타일`: 현재 이동으로 들어가는 타일

## 2. 핵심 게임 규칙

### 2.1 이동 기본 규칙

- 이동은 상하좌우 인접 타일로만 가능하다.
- 대각선 이동은 허용하지 않는다.
- 이동 시 감소 판정은 목적지에 "들어갈 때"가 아니라 출발 타일을 "떠날 때" 발생한다.
- 즉, `A -> B` 이동 시 기본적으로 `A.count -= 1` 이 먼저 적용된다.
- 손을 뗀 마지막 타일은 즉시 감소하지 않으며, 다음 이동에서 그 타일을 떠날 때 감소한다.

### 2.2 승리 조건

- 스테이지 내 모든 활성 타일의 `count`가 정확히 `0`이 되면 클리어다.
- 구현 관점에서는 남은 전체 `count` 합이 `0`이 되는 시점이 승리 시점이다.
- 마지막에 서 있는 타일도 결국 한 번은 출발 타일로 소비되어야 하므로, 단순히 "모든 타일을 방문"했다고 해서 클리어되는 것은 아니다.

### 2.3 타일이 없어지는 조건

- 스테이지 JSON에서 `count <= 0` 인 셀은 생성 대상이 아니며, 맵에 타일이 없는 것으로 취급한다.
- 플레이 중 기존 타일의 `count`가 `0`이 되면 그 타일은 소진된 타일로 본다.
- 소진된 타일은 더 이상 출발 타일로 사용할 수 없다.
- 시뮬레이터 기본 모드에서는 `count == 0` 인 목적지 타일로의 진입은 허용할 수 있다.
- 시뮬레이터 `strict` 모드에서는 목적지 역시 `count > 0` 이어야만 진입 가능하다.

### 2.4 타일이 `-1`이 되는 조건

- 정상적인 스테이지와 유효한 이동에서는 어떤 타일도 `-1`이 되면 안 된다.
- 아래 경우 `-1`이 발생할 수 있으며, 이 경우 해당 이동은 잘못된 이동으로 간주한다.
  - 이미 `0`인 출발 타일을 떠나려고 한 경우
  - `CrossBlast` 부가 감소로 인접 타일이 `0 -> -1` 이 된 경우
  - `TwinLink` 동기 감소로 연결 타일이 `0 -> -1` 이 된 경우
- 개발 기준으로 `count < 0` 은 "허용 가능한 중간 상태"가 아니라 즉시 실패 처리해야 하는 비정상 상태다.

### 2.5 이동 판정 순서

한 번의 이동은 아래 순서로 해석하는 것이 안전하다.

1. 목적지가 인접한 실제 타일인지 확인
2. `Hidden` 진입 가능 여부 확인
3. 출발 타일이 `ShortCircuit` 인 경우 방향 조건 확인
4. 목적지 타일이 `FixedKnot` 인 경우 순번 조건 확인
5. 필요 시 목적지 `count > 0` 조건 확인 (`strict` 모드)
6. 출발 타일 `count -= 1`
7. 출발 타일 특수 효과 적용 (`CrossBlast`, `TwinLink`)
8. 목적지 타일 진입 후 `Igniter` 활성화
9. 전체 `count` 합이 `0` 인지 확인

## 3. 특수 타일 공통 원칙

- 특수 타일도 기본적으로는 일반 타일과 동일하게 출발 시 자기 자신의 `count`가 1 감소한다.
- 특수 규칙은 "기본 감소를 대체"하는 것이 아니라 "기본 감소에 추가"되는 경우가 대부분이다.
- 특수 타일의 추가 필드는 스테이지 JSON에서 명시해야 한다.
- 필수 필드가 없으면 스테이지 데이터 오류로 취급하는 것이 맞다.

## 4. 타일별 상세 규칙

### 4.1 `Normal`

- 의미: 기본 타일
- 필수 필드: 없음
- 동작:
  - 이 타일에서 출발하면 자신의 `count`만 1 감소한다.
  - 추가 제약이나 부가 효과는 없다.
- 용도:
  - 가장 기본적인 경로 구성
  - 특수 타일 사이의 완충 구간

### 4.2 `CrossBlast (CB)`

- 의미: 출발 시 주변 타일까지 함께 소모시키는 광역 감소 타일
- 필수 필드: 없음
- 동작:
  - 이 타일에서 출발하면 먼저 자기 자신의 `count`가 1 감소한다.
  - 그 다음 목적지 타일을 제외한 상하좌우 인접 타일들의 `count`를 각각 1 감소시킨다.
  - 감소 대상 중 하나라도 `-1` 이 되면 그 이동은 성립하면 안 된다.

### 4.3 `ShortCircuit (SC)`

- 의미: 출발 가능한 방향이 고정된 방향 강제 타일
- 필수 필드: `direction`
- 허용 값: 일반적으로 `Up`, `Down`, `Left`, `Right`
- 동작:
  - 이 타일에서 출발할 때, 설정된 방향으로만 이동할 수 있다.
  - 다른 방향으로의 이동 시도는 무효다.
  - 정상 방향으로 이동한 경우에는 일반 타일과 동일하게 자신의 `count`가 1 감소한다.

### 4.4 `FixedKnot (FK)`

- 의미: 특정 이동 순번에만 진입 가능한 타이밍 고정 타일
- 필수 필드: `targetOrder`
- 동작:
  - 이 타일은 "몇 번째 이동에 들어오는가"를 검사한다.
  - 현재 이동 순번이 `targetOrder` 와 정확히 일치할 때만 진입 가능하다.
  - 순번이 다르면 인접해 있어도 들어갈 수 없다.
  - 진입에 성공한 뒤의 감소는 일반 규칙과 동일하며, 이 타일을 나중에 떠날 때 자기 `count`가 감소한다.

### 4.5 `TwinLink (TL)`

- 의미: 연결된 짝 타일이 같은 타이밍에 함께 감소하는 연동 타일
- 필수 필드: `linkID`
- 동작:
  - 이 타일에서 출발하면 먼저 자신의 `count`가 1 감소한다.
  - 이어서 같은 `linkID` 를 가진 짝 타일도 같은 타이밍에 1 감소한다.
  - 짝 타일 감소 결과가 `-1` 이 되면 해당 이동은 무효다.
- 구현 주의:
  - 시뮬레이터는 "상대 타일도 직접 1 감소" 방식으로 해석한다.
  - 생성기/검증기 일부 로직은 두 타일 값을 동기화하는 형태로 해석하므로, 쌍의 초기 count를 동일하게 설계하는 것이 구현 차이를 줄인다.

### 4.6 `Igniter (IG)`

- 의미: 특정 `Hidden` 그룹의 잠금을 해제하는 스위치 타일
- 필수 필드: `targetID`
- 동작:
  - 이 타일 자체의 이동/감소 규칙은 일반 타일과 같다.
  - 차이는 "이 타일에 진입했을 때" 발생한다.
  - 진입 성공 시 `targetID` 와 같은 그룹이 활성화되고, 대응 `Hidden.groupID` 타일에 진입할 수 있게 된다.
- 추가 규칙:
  - 시작 타일이 `Igniter` 인 경우, 해당 그룹은 시작 시점부터 켜진 것으로 보는 구현이 안전하다.

### 4.7 `Hidden (HD)`

- 의미: 대응 `Igniter` 가 활성화되기 전까지 들어갈 수 없는 잠금 타일
- 필수 필드: `groupID`
- 동작:
  - 대응되는 `Igniter.targetID` 가 아직 활성화되지 않았다면 진입 불가다.
  - 그룹이 활성화된 뒤에는 일반 타일처럼 진입 가능하다.
  - 진입 후 감소는 일반 규칙과 같으며, 이 타일을 떠날 때 자기 `count`가 감소한다.

### 4.8 `BlindCurtain (BC)`

- 의미: 정보 은닉 또는 시각 연출용 타일
- 필수 필드: 없음
- 동작:
  - 현재 시뮬레이터 기준으로는 시각 표시용이다.
  - 별도의 진입 제약이나 감소 규칙 변화는 없다.
  - 게임 규칙 측면에서는 일반 타일처럼 취급해도 된다.

### 4.9 `Blackout (BO)`

- 의미: 시야 차단 또는 글리치 연출용 타일
- 필수 필드: 없음
- 동작:
  - 현재 시뮬레이터 기준으로는 시각 표시용이다.
  - 별도의 진입 제약이나 감소 규칙 변화는 없다.
  - 게임 규칙 측면에서는 일반 타일처럼 취급해도 된다.

## 5. 필드 요약

| 타일 | 코드 | 필수 추가 필드 | 핵심 규칙 |
| --- | --- | --- | --- |
| Normal | `Normal` | 없음 | 일반 감소만 적용 |
| CrossBlast | `CrossBlast` | 없음 | 출발 시 목적지를 제외한 인접 타일도 1 감소 |
| ShortCircuit | `ShortCircuit` | `direction` | 설정 방향으로만 출발 가능 |
| FixedKnot | `FixedKnot` | `targetOrder` | 지정 이동 순번에만 진입 가능 |
| TwinLink | `TwinLink` | `linkID` | 연결된 짝 타일이 함께 감소 |
| Igniter | `Igniter` | `targetID` | 진입 시 대응 Hidden 그룹 활성화 |
| Hidden | `Hidden` | `groupID` | 대응 Igniter 활성화 전에는 진입 불가 |
| BlindCurtain | `BlindCurtain` | 없음 | 현재는 시각 표시용 |
| Blackout | `Blackout` | 없음 | 현재는 시각 표시용 |

## 6. 스테이지 작성 시 권장 규칙

- `count <= 0` 인 셀은 아예 타일이 없는 것으로 간주하고 작성한다.
- `TwinLink` 는 같은 `linkID` 를 정확히 2개만 두고, 가능하면 같은 `count` 로 설계한다.
- `Igniter.targetID` 와 `Hidden.groupID` 는 반드시 1:1 또는 1:N 대응 관계가 추적 가능하게 명명한다.
- `ShortCircuit.direction` 은 실제로 인접 타일이 존재하는 방향만 사용한다.
- `FixedKnot.targetOrder` 는 실제 해답 경로 길이 안에 들어오는 값으로 설정한다.
- `CrossBlast` 주변에 `count == 1` 타일을 둘 경우, 부가 감소로 즉시 소진될 수 있음을 전제로 설계한다.

## 7. 구현 메모

- 현재 저장소에는 "목적지 `count == 0` 진입 허용" 해석과 "`strict` 모드에서만 금지" 해석이 함께 존재한다.
- 따라서 문서/시뮬레이터/UI에서는 "기본 모드"와 "`strict` 해석"을 분리해서 표현하는 것이 좋다.
- `BlindCurtain`, `Blackout` 은 현재 규칙 변경 타일이 아니라 표시 전용 타일로 유지하는 것이 문서와 구현을 일치시키는 방법이다.
