# ZeroStep 타일 규칙 (기준 문서)

> 이 문서는 **실제 게임 코드(`GameManager.cs`)가 판정하는 규칙**을 기준으로 정리한 단일 기준 문서다.
> 스테이지 생성·검증 도구(`Tools/StagePipeline`), 힌트 솔버, 스테이지 검증기(`StageDataValidator`)는 모두 이 규칙을 따라야 한다.
> 규칙을 바꾸면 이 문서, 힌트 솔버(`TryApplyHintStep`), 실패 판정, 파이썬 솔버를 함께 고치고 `StageReplayTests`로 1,000개 스테이지를 다시 검증한다.
> (`rule_check.md`, `rule_plan.md`는 과거 기록이며 이 문서와 다르면 이 문서가 우선한다.)

## 1. 기본 규칙

- 시작 칸(`startPoint`)에서 드래그를 시작해 상하좌우로 인접한 칸으로 이동한다. 대각선 불가.
- 들어갈 수 있는 칸: 숫자(`count`)가 1 이상이고, 잠긴 Hidden이 아닌 칸. 이미 지나간 칸도 숫자가 남아 있으면 다시 들어갈 수 있다.
- **떠날 때 1 감소**: `A → B` 이동 시 `A`의 숫자가 1 줄어든다. 손을 떼고 멈춘 칸은 다음에 떠날 때 줄어든다.
- 손을 떼면 그 칸이 다음 드래그의 시작점이 된다. 손을 뗀 것은 TwinLink의 "직전 칸" 판정에만 영향을 준다.

## 2. 승리와 실패

- **승리**: 칸에 들어간 직후, 그 칸의 숫자가 1이고 보드 전체 합이 1이면 클리어(마지막 칸은 떠날 필요가 없다).
  - TwinLink 변형: 들어간 칸이 TwinLink이고, 남은 숫자가 그 칸과 짝 칸들(모두 1)뿐이면 클리어.
  - 특수 효과가 없는 판의 정답은 정확히 `(전체 합 - 1)`번 이동이다.
- **실패(게임오버)**
  - 현재 칸에서 규칙상 갈 수 있는 칸이 없다.
  - 아직 한 번도 밟지 않은 FixedKnot의 순서가 지났다(남은 숫자가 있고, 이동 수 ≥ `targetOrder`).
  - 실패 판정기는 "남은 칸 중 다시는 닿을 수 없는 칸"이 생기면 미리 실패로 판정한다(조기 감지).
- 실패하면 하트 1개가 줄고 스테이지가 처음 상태로 돌아간다. 수동 리셋과 되돌리기는 하트를 쓰지 않는다.

## 3. 한 번의 이동 처리 순서

1. 이동 가능 판정: 인접 여부 → ShortCircuit(진입·출구) → FixedKnot 순서 → TwinLink 짝 소비 가능 여부
2. 떠나는 칸 `-1`
3. 떠나는 칸의 효과: TwinLink(짝 감소) → CrossBlast(이웃 감소, 연출상 0.07초 뒤 적용) → Charge(이웃 +1)
4. 들어간 칸의 효과: Blackout(전체 `?`) → Igniter(Hidden 열기) → FixedKnot(순서 충족)
5. FixedKnot 놓침 검사 → 승리 검사 → (손을 뗄 때) 실패 검사

## 4. 특수 타일

| 타입 | 한글 이름 | 규칙 |
| --- | --- | --- |
| `ShortCircuit` | 한방향 타일 | `direction` 쪽 칸으로만 나갈 수 있고, 그 칸에서는 들어올 수 없다. `Up`=y+1. |
| `CrossBlast` | 십자폭발 타일 | 떠날 때 상하좌우 이웃 중 숫자가 남은 칸(들어가는 칸 제외, 직전 칸·잠긴 Hidden 포함)을 1씩 줄인다. |
| `FixedKnot` | 순서 타일 | 처음 진입은 `targetOrder`번째 이동에서만 가능. 지나면 실패. 진입한 뒤에는 일반 타일. 시작점 거리와 `targetOrder`의 홀짝이 다르면 절대 진입할 수 없다. `isAbsolute`는 현재 판정에 쓰지 않는다. |
| `TwinLink` | 짝꿍 타일 | 떠날 때 같은 `linkID`의 짝 칸들을 1씩 줄인다(들어가는 칸과, 현재 드래그의 직전 칸은 제외). 손을 떼면 직전 칸이 초기화된다. |
| `Igniter` / `Hidden` | 켜기 타일 / 숨은 타일 | Igniter에 들어가는 순간 `targetID`와 같은 `groupID`의 Hidden이 즉시 열린다(등장 연출만 0.08초 간격으로 순서대로 보인다). 시작 칸이 Igniter면 시작과 동시에 열린다. 잠긴 Hidden은 들어갈 수 없지만 CrossBlast의 영향은 받는다. |
| `BlindCurtain` | 가림 타일 | 규칙은 일반 타일과 같고 자기 숫자만 `?`로 보인다. |
| `Blackout` | 깜깜 타일 | 규칙은 일반 타일과 같다. 밟는 순간 이번 시도 동안 보드 전체 숫자가 `?`로 바뀐다. |
| `Charge` (신규) | 충전 타일 | 떠날 때 자기는 1 줄고, 상하좌우 이웃 중 숫자가 남은 칸(들어가는 칸 제외)을 1씩 늘린다. FixedKnot·Igniter·Hidden은 영향받지 않고, 0인 칸은 되살리지 않으며, 연쇄되지 않는다. |

`Spotlight`는 타일이 아니라 `config.mode`이며 현재 스테이지 데이터에서는 쓰지 않는다.

## 5. 데이터 규칙 (검증기가 확인)

- `stage_1.json` ~ `stage_1000.json`, `stageID` = 파일 번호, 보드 최대 10×10(권장 가로 7·세로 8 이하).
- 시작 칸에 타일이 있어야 하고 Hidden이면 안 된다.
- Hidden 그룹마다 그 그룹을 여는 Igniter가 있어야 한다. TwinLink 그룹은 2칸 이상.
- `Resources/Stages/solutions.txt`에 모든 스테이지의 검증된 정답이 있어야 한다.
  - 형식: `N|x,y;x,y;...|x,y;...` — `|`로 나뉜 구간이 손을 떼지 않는 한 번의 드래그이고, 각 구간의 첫 칸은 현재 위치다.
  - 힌트는 플레이어가 이 정답 위에 있으면 탐색 없이 즉시 표시된다(실제 규칙으로 끝까지 재생해 확인한 뒤에만 사용).

## 6. 검증 방법

- 정적 검증: Unity 메뉴 `ZeroStep/Validate Stage Data` (빌드 직전 자동 실행, 오류가 있으면 빌드 실패)
- 엔진 재생 검증: `StageReplayTests` — 실제 `GameManager` 규칙 코드로 1,000개 정답을 재생해 모두 클리어되는지와 힌트 가능 여부를 확인
- 파이썬 도구: `Tools/StagePipeline/validate.py` — 규칙 모델 솔버로 풀이 가능·난이도·메커닉 의미 여부를 확인
