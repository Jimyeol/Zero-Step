## 1. 진행을 막는 버그 (P0)

### B1. 하트 소진 시 빠져나갈 수 없음 [확인]

**현상**

- 하트 소진 팝업에는 "광고 보고 충전" 버튼만 있고 닫기 버튼이 없습니다(`Assets/Resources/GameMainUI.uxml:214-221`).
- 팝업이 설정, 힌트, 스킵을 모두 가립니다.
- 버튼은 보상형 광고가 로드될 때까지 비활성 상태입니다(`GameMainUIController.cs:3519-3528`).
- 광고 로드에 실패하면 재시도가 없습니다. 실패 메시지는 곧바로 "광고 불러오는 중…"으로 덮어써집니다(`:6655-6666`).
- 10분·20분 무료 충전은 팝업이 열려 있는 동안 플레이 시간이 쌓이지 않아 영영 도착하지 않습니다(`GameManager.cs:774-777`).
- 앱을 껐다 켜면 하트 0개로 복원되어 한 번 시도한 뒤 다시 팝업이 뜹니다.

**개선**

1. 팝업에 대체 경로를 추가합니다.
   - 예: "잠시 후 1개 충전" 타이머(3~5분), 또는 "이전 스테이지 복습", 또는 닫고 다른 스테이지 보기
2. 광고 로드 실패 시 재시도를 넣습니다.
   - 지수 백오프로 5초, 15초, 45초
   - 실패 문구가 덮어써지지 않도록 수정
3. 오프라인이면 "인터넷 연결이 없어요" 문구와 함께 무료 충전 경로만 보여줍니다.
4. 팝업이 열려 있어도 세션 플레이 시간이 누적되게 하거나, 무료 충전 조건을 "팝업 대기 시간"으로 바꿉니다.

**검증:** 비행기 모드로 하트 5개를 모두 잃었을 때 앱을 재시작하지 않고 진행할 수 있어야 합니다.

### B2. 풀 수 없는 스테이지 448, 702, 743 [확인]

**원인**

- 실제 게임 규칙에서는 FixedKnot을 자기 순서까지 밟지 않으면 게임오버입니다.
- 그런데 스테이지 생성 당시 규칙 문서(`Assets/rules/TILE_RULES.md`)에는 이 "놓침" 규칙이 없었습니다.
- 그 결과, 순서가 지난 FixedKnot을 CrossBlast로 지우는 풀이를 전제로 만든 스테이지가 생겼습니다.

| 스테이지 | FixedKnot 위치 | 현재 `targetOrder` | 불가능한 이유 |
| --- | --- | --- | --- |
| 448 | (2,2) | 8 | 시작점(0,1)에서 홀수 칸 거리인데 순서가 짝수. 체커보드 특성상 8번째 이동에 그 칸에 설 수 없음 |
| 702 | (1,2) | 2 | 시작점(0,0)에서 3칸 거리인데 2번째 이동에 도달해야 함 |
| 743 | (1,1) | 7 | 홀짝은 맞지만, 유일한 풀이가 순서 이후 CrossBlast로 지우는 방식 |

**개선: `targetOrder`만 바꾸는 최소 수정** [확인: 솔버로 계산]

| 스테이지 | 추천 값 | 그 값의 해답 수 / 무작위 클리어 확률 | 다른 후보 |
| --- | --- | --- | --- |
| 448 | 9 | 127 / 약 0.1% (주변 스테이지보다 확연히 어려움) | 7 (42 / 0.05% 미만), 11 |
| 702 | 3 또는 4 | 1 / 8~17% (주변과 비슷) | 5~14 |
| 743 | 5 또는 11 | 1~3 / 3~6% (주변과 비슷) | 1, 3, 12~19 |

> 수정 후에는 게임 안에서 직접 한 번씩 클리어해 확인하세요.  
> 448은 9로 바꾸면 주변보다 어려워지므로 보스 스테이지 위치로 옮기는 것도 고려할 만합니다(L3 참고).

**재발 방지**

- 에디터 메뉴로 실행하는 **스테이지 검증기**를 만들고, 빌드 전에 자동 실행합니다(L2).
- 최소한 다음 두 가지는 검사해야 합니다.
  - FixedKnot의 홀짝 검사: `(|x−sx| + |y−sy|) % 2 == targetOrder % 2`
  - 솔버로 풀이 1개 이상 존재 확인
- 규칙을 하나로 정리합니다. 게임 규칙을 바꿨다면 `TILE_RULES.md`와 `Assets/rules/rule_check.md`도 함께 갱신합니다.

### B3. 1000스테이지에서 스킵하면 1스테이지로 돌아감 [확인]

**현상**

- `LoadNextStageImmediate`가 `TryAdvanceToNextStage`를 호출합니다(`GameManager.cs:595-603`).
- 1001번 파일이 없으면 `currentStageIndex = 1`로 돌아가고 그대로 저장됩니다(`GameManager.cs:5175-5191`).
- 엔딩 크레딧은 정상 클리어 경로에서만 실행됩니다.

**개선**

1. 최종 스테이지에서는 스킵 버튼을 비활성화하거나 숨깁니다.
2. 굳이 허용한다면 스킵 시에도 엔딩 경로(`FinalEndingProgressStore`)로 보냅니다.
3. `TryAdvanceToNextStage`의 1스테이지 순환을 없애고, 다음 파일이 없으면 엔딩이나 오류 처리로 보냅니다.
4. 스킵에 확인 팝업을 붙입니다. 스킵은 되돌릴 수 없고 레벨 선택도 없기 때문입니다.

### B4. 배너·하단 버튼 간격이 잘못된 단위로 계산됨 [확인 + 추정]

**원인** [확인]

- UI Toolkit 패널은 가로 1080 기준으로 스케일됩니다(`Assets/Resources/SettingUI.asset`: `m_ScaleMode: 2`, `m_ReferenceResolution: 1080×1920`, `m_Match: 0`).
  - 따라서 UI 1단위 = `Screen.width / 1080` 화면 픽셀입니다.
- 그런데 `RefreshBottomLayout`(`GameMainUIController.cs:7151-7215`)은 **화면 픽셀 값을 UI 단위에 그대로** 넣습니다.
  - 배너 높이: `bannerView.GetHeightInPixels()`, `ConvertDpToPixels()` 반환값
  - safe area 여백: `currentSafeArea.yMin` 등
  - 이 값들이 `bottomBar.style.bottom`, `bannerAdContainer.style.height`, `topBar.style.paddingTop`에 그대로 들어갑니다.

**결과** [추정: 계산]

| 화면 폭 | UI 1단위 | 결과 |
| --- | --- | --- |
| 720px (보급형 HD+) | 0.67px | 확보 공간이 실제 배너보다 작음 → **하단 버튼이 배너 위로 겹침**(약 10~30px) |
| 1080px | 1px | 의도대로 동작하지만 간격이 빠듯함 |
| 1440px (QHD) | 1.33px | 공간이 과하게 확보되어 보드가 작아짐 |

- 상단 노치 여백(safe area top)도 같은 문제가 있습니다. 좁은 폰에서는 HUD가 노치에 가려질 수 있습니다.
- 게임 보드 크기 계산이 이 값을 기반으로 하므로 보드 배치도 함께 어긋날 수 있습니다.

**개선**

```csharp

private float ScreenPxToPanel(float px)
{
    var root = uiDocument != null ? uiDocument.rootVisualElement : null;
    float panelWidth = root != null ? root.resolvedStyle.width : 0f;
    if (panelWidth <= 0f || float.IsNaN(panelWidth) || Screen.width <= 0)
        return px;
    return px * (panelWidth / Screen.width);
}
```

1. safe area(상하좌우), 배너 높이, 여분 간격을 모두 변환한 뒤 `style`에 넣습니다.
   - 또는 `RuntimePanelUtils.ScreenToPanel`을 사용합니다.
2. 배너와 버튼 사이에 **최소 간격을 dp 기준으로 보장**합니다(예: 16~24dp를 변환한 값).
3. `ConvertDpToPixels`는 `Screen.dpi`에 의존해 기기마다 오차가 있습니다. 배너가 로드된 뒤에는 `GetHeightInPixels()` 값만 쓰도록 통일합니다.
4. 배너 로드 실패 시 표시되는 "AD LOAD FAILED" 문구를 없애고, 빈 영역으로 둡니다(`GameLocalization.cs:235-238`).
5. 앱 시작 스플래시 위에는 배너를 띄우지 않습니다. 스플래시가 닫힌 뒤 `Show()`합니다(`:7060-7064`).

**검증 매트릭스**

- Device Simulator 해상도: 720×1280, 720×1600, 1080×2400, 1440×3200, iPad 4:3, 폴더블
- 실기기: 720 폭 폰 1대 이상
- 매 해상도에서 확인할 것: 하단 버튼 하단과 배너 상단 사이 간격, 상단 HUD와 노치 사이 간격

### B5. 게임 사운드가 빌드에 포함되지 않을 가능성 [확인 + 추정]

- 효과음 필드(`blockAClip` 등, `GameManager.cs:150~`)는 에디터 전용 `OnValidate`에서만 자동 할당됩니다(`GameManager.cs:6095-6131`, `#if UNITY_EDITOR`).
- 씬 파일(`SampleScene.unity`)에는 이 필드들이 저장되어 있지 않습니다.
- 따라서 기기 빌드에서는 null이 되어 **이동 멜로디, 폭발음, 클리어음이 나지 않을 가능성이 높습니다.**

**개선**

- 씬을 열고 GameManager를 한 번 선택해 할당된 상태로 **씬을 저장**합니다.
- 더 나은 방법: 클립을 `Resources/Sounds`로 옮기고 런타임에 로드하거나, `ScriptableObject` 사운드 뱅크로 묶습니다.
- 실기기에서 소리가 나는지 반드시 확인합니다.

### B6. 힌트 솔버 규칙이 실제 게임과 다름 [확인: 솔버 비교]

- 힌트 솔버는 CrossBlast가 **아직 잠긴 Hidden 타일**을 건너뛴다고 모델링합니다. 실제 게임은 잠긴 Hidden도 감소시킵니다.
- 영향:
  - **755:** 유일한 풀이가 이 동작에 의존해서 힌트가 처음부터 "풀이 없음"이 됩니다.
  - **222, 223, 608, 615, 842, 852, 875:** 힌트가 실제로는 막다른 길로 안내할 수 있습니다.

**개선**

- 힌트 솔버의 CrossBlast 처리를 실제 게임과 동일하게 맞춥니다.
- 장기적으로는 **실제 게임과 힌트가 같은 규칙 코드**를 쓰도록 순수 C# 규칙 엔진(`BoardState` + `ApplyMove`)으로 분리합니다.
- 분리한 규칙 엔진은 검증기(L2)에서도 그대로 재사용합니다.

### B7. BlindCurtain·Blackout 아이콘이 튜토리얼과 게임에서 뒤바뀜 [확인]

- 튜토리얼: BlindCurtain = 눈 가림 아이콘(`blind_curtain_tile`), Blackout = "?"(`GameMainUIController.cs:131, 4850, 4863-4875`)
- 실제 게임: Blackout이 눈 가림 아이콘을 사용하고(`BlackoutTile.cs:13`), BlindCurtain은 "?"만 표시합니다.
- `Sprites/black_out_tile.png`("?" 아이콘)는 어디에서도 쓰이지 않습니다.

**개선:** `BlackoutTile.tileSpritePath`를 `Sprites/black_out_tile`로 바꾸거나, 튜토리얼 쪽을 게임에 맞춥니다. 둘 중 하나로 통일하면 됩니다.

### B8. 광고 미준비 시 힌트·스킵 버튼이 무반응 [확인]

- 충전이 0일 때 보상형 광고가 준비되지 않았으면 분석 이벤트만 남기고 아무것도 보여주지 않습니다(`GameMainUIController.cs:6830-6835`).

**개선:** 스낵바로 "광고를 불러오는 중이에요. 다음 충전까지 12:30" 같은 상태를 알려줍니다. 버튼에 충전 타이머를 항상 노출합니다.

## 2. 애니메이션·게임 손맛 (P1)

### 현재 핵심 루프 시간 [확인]

| 이벤트 | 입력 잠금 | 실제 다시 플레이 가능까지 |
| --- | --- | --- |
| 스테이지 클리어 | 0.5초 고정 | 약 0.6~0.9초 |
| 게임오버 | 전체 시퀀스 동안 잠금 | 12타일 약 1.0초, 34타일 약 1.8초 |
| 수동 리셋 | 타일 등장 연출 동안 잠금 | 12타일 약 0.4초 |

- 탭으로 건너뛸 수 없습니다.
- 30스테이지 세션 기준 약 1.3분이 대기 시간이고, 그중 60%가 실패 루프입니다. [추정]

### A1. 실패 이유가 보이지 않음 (가장 중요) [확인]

**현상**

- 실패를 감지한 같은 프레임에 원인 타일 강조(0.28초)와 글리치 연출이 동시에 시작됩니다(`GameManager.cs:3882-3885`).
- 약 0.1초 만에 보드 전체가 암전되어 원인 강조를 덮어버립니다.
- FixedKnot "놓침" 흔들림(0.35초)도 암전 시작과 함께 끊깁니다(`FixedKnotTile.cs:841-857`).
- 남는 건 원인 타일과 떨어진 곳에 뜨는 2.2초짜리 스낵바뿐입니다.

**개선: "왜 졌는지 0.5초 보여주고, 빠르게 재시작"**

1. 0~0.45초: 원인 타일 펄스, 나머지 타일 30%로 어둡게.
   - 도달 불가 영역은 외곽선 표시
   - FixedKnot은 "N번째 이동 필요 → 지금 N+1" 표시
2. 0.45~0.6초: 한 번만 부드럽게 어두워짐(스트로브 없음)
3. 이후 재시작 연출을 0.25초로 제한
4. 0.2초 이후에는 탭으로 즉시 재시작 가능
5. 목표: 총 0.6~0.8초, 탭하면 약 0.3초

### A2. 게임오버 글리치의 광과민 위험 [확인]

**현상**

- 실패 연출이 보드 전체를 검정↔HDR 네온으로 25ms 간격(약 20~30Hz) 깜빡입니다(`GameManager.cs:4683-4704`).
- Bloom이 켜져 있고, 효과 강도 설정(Full/Reduced/Minimal)을 무시합니다.
- 실패할 때마다 1초 안에 약 3번 번쩍입니다. WCAG 기준 경계선입니다. [추정]

**개선**

- 스트로브를 **120~150ms 단일 디밍**으로 교체합니다.
- 실패 연출, Blackout 플리커, TwinLink 번개를 모두 `GameplayFeedback.Intensity`로 조절합니다.
- OS의 "동작 줄이기" 설정을 읽어 기본값을 Reduced로 둡니다.
  - iOS: `UIAccessibilityIsReduceMotionEnabled`
  - Android: `ANIMATOR_DURATION_SCALE == 0`

### A3. 실패·리셋 후 입력 잠금이 필요 이상으로 김 [확인]

- 재시작 타일 등장 연출이 타일 수에 비례하고 상한이 없으며, 끝날 때까지 입력을 막습니다(`GameManager.cs:4722-4735, 4767, 4859-4873, 4902`).
- 반면 스테이지 시작 연출은 0.36초로 제한되어 있고 입력을 막지 않습니다.

**개선**

- 재시작에도 스테이지 시작 연출(상한 0.36초 → 0.25초)을 재사용합니다.
- 시작 타일이 튀어나오기 시작하면 바로 입력을 허용합니다.

### A4. 이동 피드백의 가독성 [확인]

**현상**

- 숫자는 타일을 떠나는 순간 즉시 바뀝니다. 그러나 현재 서 있는 타일에 "곧 1 줄어든다"는 예고가 없습니다.
- 수락된 경로를 따라 남는 선이 없습니다.
  - `LinkSystem.CreateLinksForCrossBlastOnly`는 링크를 지우기만 합니다(`LinkSystem.cs:16-19`).
  - 트레일은 손가락의 실제 궤적(거부된 이동 포함)을 따라가고, 손을 떼면 즉시 지워집니다.
- 드래그 중 현재 머리 타일에 표시가 없습니다.

**개선**

- 머리 타일:
  - 1.08배 확대와 글로우
  - 숫자를 15% 흐리게 하거나 작게 "N−1" 고스트 표시
- 숫자 변화에 80~120ms 롤 애니메이션을 넣습니다.
- 경로선:
  - **수락된 타일 중심을 잇는 경로선**을 그리고, 손을 떼면 0.3초에 걸쳐 페이드
  - 트레일은 즉시 지우지 말고 0.15초 페이드
- Minimal 설정에서도 0.95배 눌림은 남겨 피드백이 0이 되지 않게 합니다.

### A5. 연쇄 효과의 순서가 어긋나고 시끄러움 [확인]

- **CrossBlast:**
  - 폭발음과 섬광은 0초, 이웃 감소는 0.07초입니다.
  - 그런데 빔이 이웃에 닿는 건 0.21초여서 **결과가 원인보다 먼저** 보입니다(`CrossBlastTile.cs:213-300`).
  - 서로 다른 색의 빔 두 종류와 금색 스파크가 겹칩니다.
- **TwinLink:** 짝 타일 감소는 0초인데 빔은 0.09초에 도착합니다.

**개선**

- 빔 이동은 0.06~0.07초로 하고, **빔이 도착한 순간 숫자를 감소**시킵니다.
- 메커닉당 빔 한 겹, 색 한 가지로 정리합니다.

### A6. FixedKnot이 매 이동마다 360° 회전 [확인]

- 잠긴 FixedKnot 전부가 매 이동마다 0.18초 회전하고, 1.15초 주기 맥동도 계속합니다(`FixedKnotTile.cs:514-547, 637-666`).
- 효과 강도 설정을 무시합니다.

**개선:** 카운트다운 숫자만 1.1배로 0.12초 튀게 하고, 회전은 없앱니다. 효과 강도 설정을 적용합니다.

### A7. 특수 타일 규칙이 밟기 전에 보이지 않음 [확인]

| 타일 | 문제 | 개선 |
| --- | --- | --- |
| ShortCircuit | 들어올 수 없는 방향을 거부된 뒤 스낵바로만 알 수 있음 | 출구 방향으로 흐르는 쉐브론(0.8초 주기), 진입 금지 면에 표시 |
| FixedKnot | 상태를 빨강/초록 색으로만 구분(색약 위험). 스낵바 문구가 "N번째 이동"인데 실제 값은 남은 이동 수 | 자물쇠/체크 아이콘 추가, "N수 후" 표기로 통일 |
| TwinLink | 링크 색(주황, 노랑, 라임, 보라, 빨강)이 숫자 색과 겹치고, 숫자까지 링크 색으로 칠해져 숫자 색의 의미가 사라짐 | 숫자는 숫자 색 유지, 링크 색은 테두리·배지에만. 짝 타일끼리 희미한 연결선 |
| Hidden/Igniter | Hidden이 완전히 투명. Igniter 여러 개가 같은 아이콘(62개 스테이지). 공개가 타일당 0.08초씩 순차라 최대 1.28초 걸리고, 빠르게 드래그하면 아직 안 나타난 칸에서 조용히 실패 | 그룹 색으로 칠한 반투명 자리표시, Igniter 발동 시 콜라이더 즉시 활성화 |
| Blackout | "?" 맥동·흔들림 코드가 `LateUpdate`에서 매번 텍스트를 숨겨 실행되지 않음(`BlackoutTile.cs:197-250`) | 의도한 연출이 보이도록 수정하거나 코드 삭제 |

### A8. 스테이지 클리어가 밋밋함 [확인]

**현상**

- 모든 연출이 0.5초 안에 끝나고, 클리어 웨이브(0.55초)는 91% 지점에서 잘립니다.
- HUD 글로우는 트랜지션 없이 3단계로 툭툭 바뀝니다(`GameMainUIController.cs:7522-7552`).
- 클리어 링이 게임 영역 경계에 잘려 D자 모양으로 보입니다(`docs/feedback-qa/tall-phone-clear.png`).
- 마지막 멜로디 음이 해결감 있게 끝나지 않습니다.

**개선**

- 마지막 타일에서 0.12~0.15초 히트스톱 후, 으뜸음으로 끝나는 효과음을 냅니다.
- 스테이지 번호 0.25초 롤업을 넣습니다.
- 링은 잘리지 말고 페이드아웃시킵니다.
- 총 0.7초 이하로 하고, 0.3초 이후 탭하면 바로 다음 스테이지로 넘어가게 합니다.
- 보스·챕터 클리어(L3)에는 더 큰 연출을 따로 둡니다. 연출에 위계가 생겨야 클리어가 특별해집니다.

### A9. 햅틱이 약하고 드묾 [확인]

- Android 클리어 진동이 20ms, 세기 30/255로 거의 느껴지지 않습니다.
- iOS는 항상 Light 스타일입니다.
- 이동, 거부, 실패에는 햅틱이 없습니다. 이동 4, 8, 12회째에만 울리는데 이 기준은 의미가 없습니다.

**개선:** 이동마다 selection 햅틱(40ms 스로틀), 거부된 이동에 warning, 실패에 error, 클리어에 success를 넣습니다.

### A10. UI 모션이 일관되지 않음 [확인]

- 설정 팝업은 즉시 열리고 닫히는데, 다른 팝업은 0.14~0.16초 페이드·스케일로 열립니다.
- 버튼 눌림 애니메이션이 손을 뗀 뒤(`clicked`)에 실행되어 늦게 느껴집니다(`GameMainUIController.cs:1207`).
- HUD가 4·8·12회 이동에 펄스해서 존재하지 않는 콤보가 있는 것처럼 보입니다.

**개선**

- 모든 팝업에 0.14초 공통 열기·닫기를 적용합니다.
- 눌림은 `PointerDown`에서 시작합니다.
- HUD 펄스는 0.12초 트랜지션을 주거나 제거합니다.

### A11. 힌트 미리보기 가독성 [확인]

- 화면을 터치하는 순간 힌트가 사라져 3~8수를 외워야 합니다(`GameManager.cs:1177`).
- 한 번의 1.15초 스윕이 경로 전체를 지나가서 구간당 0.14~0.38초밖에 안 됩니다.
- 같은 칸을 다시 지나는 경로는 선이 겹칩니다.
- 라임색 힌트가 숫자 2·8의 색과 비슷합니다.

**개선**

- 드래그 중에도 흐린 힌트를 유지하고, 따라 그린 구간부터 지웁니다.
- 구간마다 화살표를 넣고 구간당 0.25초로 늦춥니다.
- 힌트 전용 색을 정합니다.

### A12. 효과 강도 설정의 빈틈 [확인]

설정과 무관하게 계속 움직이는 것들:

- TwinLink 번개(5Hz)
- Blackout 플리커와 "?" 뒤집기
- 배경 스크롤
- 시작 타일 심장박동
- 힌트 화살표 펄스
- FixedKnot 회전

**개선:** 모두 `Intensity`에 비례하게 하고, Minimal에서는 완전히 정지하게 합니다.

### A13. 앱 시작이 7.5~11.5초 [확인]

- Unity 스플래시(Dolly 애니메이션)가 켜져 있습니다.
- 그 뒤 5.04초짜리 스플래시 영상이 나옵니다(7.5MB).
- 이어서 **광고 4종이 준비될 때까지** 최대 8초를 기다리고, 0.35초 페이드가 붙습니다(`GameMainUIController.cs:268-271, 3170-3204`).
- 탭으로 건너뛸 수 없고 매번 실행됩니다.

**개선**

- Unity 스플래시를 끕니다(Unity 6부터 Personal 라이선스도 끌 수 있음. Player Settings > Splash Image).

## 4. 지루하지 않게 만들기: 레벨 디자인 (P1)

### 분석 요약 [확인: 솔버로 1,000개 전수 분석]

- **풀이 가능:** 997/1000. 튜토리얼은 각 메커닉 첫 등장 스테이지와 정확히 맞물립니다.
- **난이도 추세 없음:** 30스테이지부터 1000스테이지까지 스테이지 번호와 난이도의 상관계수는 −0.04입니다. 오히려 200~400 구간이 가장 어렵고 이후 조금씩 쉬워집니다.
- **새 메커닉 등장:**

  | 스테이지 | 메커닉 |
  | --- | --- |
  | 50 | ShortCircuit |
  | 100 | CrossBlast |
  | 115 | FixedKnot |
  | 140 | TwinLink |
  | 170 | Igniter/Hidden |
  | 200 | BlindCurtain |
  | 230 | Blackout |

  **230 이후 770개 스테이지에는 새로운 것이 없습니다.**
- 200 이후 100스테이지 구간마다 37~52%는 규칙을 바꾸는 특수 타일이 없습니다.
- 100 이후 **117개 스테이지는 무작위로 움직여도 50% 이상 클리어**되고, 18개는 실패 자체가 불가능합니다.
- 평균적인 스테이지는 19수 중 **정말 고민이 필요한 수가 약 3개**입니다.

### L1. 풀 수 없는 스테이지 수정

B2 참고.

### L2. 스테이지 검증기와 지표 리포트 도구

1. 게임과 같은 규칙 엔진(B6)을 사용하는 에디터 도구를 만들고, 각 스테이지에 대해 다음을 CSV로 출력합니다.
   - 풀이 가능 여부, 해답 수
   - 무작위 클리어 확률
   - 결정적 수(잘못 두면 지는 수) 개수
   - 강제 수 비율
   - 사용 메커닉
2. 빌드 전 자동 실행하고, 풀 수 없는 스테이지가 있으면 빌드를 실패시킵니다.
3. 이 분석에 쓴 파이썬 솔버를 참고 구현으로 활용할 수 있습니다. 위치는 세션 임시 폴더라 필요하면 저장소로 옮겨야 합니다.
4. Firebase `stage_fail`, `stage_reset`, `hint` 이벤트를 스테이지별로 집계해 **실제 플레이어 난이도**와 솔버 난이도를 비교합니다.

### L3. 난이도 곡선 재정렬: "올라가는 톱니"

- 50스테이지를 한 챕터로 묶습니다(20챕터).
- 각 챕터는 다음 구조를 갖습니다.
  - **도입(1~5):** 그 챕터의 핵심 메커닉을 쉬운 판으로 다시 보여줌
  - **본편(6~45):** 난이도가 서서히 오르되 5~8스테이지마다 쉬어가는 판 1개
  - **보스(50):** 챕터에서 가장 어려운 판, 전용 클리어 연출(A8)
- 챕터가 넘어갈 때마다 기준 난이도를 한 단계 올립니다.
- 보스 후보(현재 가장 어려운 스테이지들): 397, 225, 138, 635, 913, 189, 359, 994, 263, 453, 801, 712, 432, 946, 92, 435, 80, 716, 909, 125
- 지금 바로 고칠 만한 급격한 난이도 튐: 138(TwinLink 도입 직전, 주변은 쉬움), 397, 225. 보스 자리로 옮기거나 앞뒤 순서를 조정합니다.
- 1~1000 전체를 다시 쓰는 대신, **기존 스테이지를 지표 기준으로 재배치**하는 것만으로도 큰 효과가 있습니다.

- 300 이후 스테이지당 규칙 변경 메커닉은 평균 0.8~1.0개입니다. 3종 이상 조합은 100스테이지당 2~14개뿐입니다.

### L8. 보드 모양 다양화

- 455개 스테이지가 다른 스테이지와 같은 외곽 모양을 공유합니다. 대부분 꽉 찬 직사각형입니다.

### L9. 초반 1~50 압축

**현상**

- 30~49는 거의 같은 4×4 보드가 20번 이어지고, 판마다 28~41수로 깁니다.
- 첫 특수 타일이 50스테이지에야 나옵니다.

**개선**

- 30~49의 긴 4×4 보드는 절반으로 줄이거나 뒤로 분산합니다.
- 첫 세션(약 10분) 안에 최소 한 개의 새 메커닉을 보게 합니다.

### R2. 시행착오 처벌 완화

**현재** [확인]

- 2수 이상 움직인 뒤 리셋하면 하트가 1개 줄어듭니다(`GameManager.cs:182, 4771-4791`).
- 리셋 버튼에 비용 표시가 없고, 되돌리기가 없습니다.
- 막힌 상태에서 힌트를 누르면 "여기서는 풀 수 없어요, 다시 시작하세요"가 나와서 결국 하트를 쓰는 리셋으로 유도합니다.
- 퍼즐 게임에서 실험은 핵심 재미인데, 실험할 때마다 하트를 잃습니다.

**개선**

1. **되돌리기(Undo):** 마지막 이동 취소. 무제한이 부담되면 스테이지당 3회.
2. **수동 리셋은 무료로**, 하트는 게임오버에만 차감합니다. 최소한 리셋 버튼에 하트 아이콘을 표시합니다.
3. "풀 수 없는 상태"를 감지하면 즉시 알려줍니다. 이미 조기 감지 로직이 있으므로, 하트 차감 없이 "몇 수 전으로 돌아가기"를 제안합니다.
4. 하트 수, 리셋 비용, 무료 충전 시간을 Remote Config로 조절해 A/B 테스트합니다.
